## 3. 共通レイアウト

### グローバルヘッダー (全画面)

| 要素 | 表示条件 | 640px 未満 |
|---|---|---|
| ロゴ / サイト名 (左) | 常時 | ログイン中は ✈️ だけにする (リンクの名前は「trip-diary」のまま) |
| ダークモードの切り替え | 常時 | 同じ |
| 通知ベル | ログイン時のみ | 同じ |
| 「+ 新しい旅行記録」ボタン | ログイン時のみ | 「+」だけにする (名前は「新しい旅行記録」のまま) |
| 「下書き」「★ (お気に入り)」リンク | ログイン時のみ | 同じ |
| アバター (自分のプロフィールへ) | ログイン時のみ | 同じ |
| 「ログアウト」ボタン | ログイン時のみ | アイコン (🚪) にする (名前は「ログアウト」のまま) |
| ログイン / サインアップ リンク | 未ログイン時 (サインアップは停止中は出さない) | サインアップは出さない (ログイン画面のリンクから行ける) |
| 「ゲストとして試す (登録不要)」ボタン | 未ログイン時 | 「ゲストで試す」にする |
| ゲストモードの帯「ゲストモード: 24 時間後にデータは削除されます」(ヘッダーの下) | ゲストでログイン中 | 同じ |

各項目は折り返さず (`whitespace-nowrap`)、縮めない (`shrink-0`)。幅 360px でも 1 行に収まる。検索欄はヘッダーではなく、トップの画面にある。

## 6. エラー / 空状態 デザインルール

| 状態 | 表現 |
|---|---|
| 一覧 0 件 | 「まだ旅行記録がありません。最初の記録を残しましょう」 + 新規作成ボタン |
| 404 (存在しない URL・見つからない旅行記録) | 🧭 と「ページが見つかりません」 + トップへ戻るリンク。ヘッダーはそのまま出す (`components/NotFoundMessage.vue` を `error.vue` と旅行の詳細で使う)。非公開・下書きの旅行記録も、あることを漏らさないため同じ表示 |
| 401 (未ログインで保護画面) | ログイン画面へリダイレクト |
| 403 (他人の編集画面) | 詳細画面へリダイレクト + トースト「自分の旅行記録のみ編集できます」 |
| 500 など (サーバーエラー) | エラーの画面 (`error.vue`) は「エラーが発生しました」「時間を置いて、もう一度お試しください」 + トップへ戻るリンク。旅行の詳細は「旅行記録を読み込めませんでした。時間を置いて、もう一度お試しください」。どちらも API の生の文言は出さない |

## 7. レスポンシブ方針 (Phase1)

- ブレークポイントは Tailwind デフォルト (sm:640 / md:768 / lg:1024 / xl:1280)
- カード一覧: md 以上で 2 カラム / lg 以上で 3 カラム / それ未満で 1 カラム
- フォーム: md 以上で 中央寄せ最大 720px / それ未満で 100%
- 640px 未満では、ヘッダーの項目を短くして 1 行に収める (§3 のグローバルヘッダーの表)
- 旅行の作成・編集画面は、640px 未満ではカテゴリと公開範囲を 1 列にし、保存のボタンを縦に並べて横幅いっぱいにする (「公開して保存」を上に)。入力欄と選択欄は、すべて label と `for`・`id` でつなぐ
- 幅 360px と 390px で、ヘッダーと作成画面が崩れないことを確かめた (#172)。ほかの画面のスマートフォン向けの作り込みは、今は行っていない
