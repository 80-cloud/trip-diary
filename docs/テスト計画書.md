## §1 目的とスコープ

- 「習う→慣れる→マスター」 ([学習ロードマップ.md](./学習ロードマップ.md) §1) の **慣れ** 段階で、**テストが品質の防波堤** であることを言語化する
- Phase 1 は基盤 + サンプルのみ → Phase 2 で本番品質に引き上げ → **Phase 3 で CI ゲート化 + 種別拡張** (実施済)
- **本書スコープ** (v0.2 で範囲拡大):
  - Backend Unit / Integration (Minitest)
  - Frontend Component / Composable (Vitest)
  - **E2E (Playwright Chromium smoke / WebKit / Mobile Safari)** ← v0.2 追加
  - **性能 (k6 Layer A: smoke + timeline SLO)** ← v0.2 追加
  - **静的解析 (rubocop-rails-omakase / @nuxt/eslint)** ← v0.2 追加
  - **CI 自動実行 (GitHub Actions ci.yml + e2e.yml + perf.yml)** ← v0.2 追加
  - 手動ブラックボックスチェックリスト (§8)
- **範囲外** (Phase 4 検討):
  - UI snapshot regression test (Playwright `toHaveScreenshot`)
  - 高 VU 負荷試験 (k6 Layer B 以降)
  - Web Push / リアルタイム通知 (ActionCable) の test
  - フロント a11y 自動検出 (axe-core 統合)
