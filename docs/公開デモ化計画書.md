## 1. 目的

公開 URL を開いた第三者が、**登録なしで 30 秒以内に主要機能を触れる**状態にする。

- 閲覧者は、アカウント登録の手間があるとその時点で離脱しやすい。
- 空のデータベースにログインして真っ白な画面が出ると、機能の多さが伝わらない。
- 公開環境は **月額 0 円** で維持できる構成にする (AWS 構成は 2026-05-19 に撤収済み)。

## 5. ゲストログイン設計 (F-GUEST-01)

### 5-1. 方式比較

| 観点 | A. 共有の固定デモアカウント | B. 訪問者ごとの一時ゲスト (採用) |
|---|---|---|
| 他の閲覧者の影響 | 受ける (誰かが投稿を消すと次の人は空の画面を見る) | 受けない (自分のデータは自分だけのもの) |
| パスワード | フロントのコードに埋め込む必要がある | 不要 (サーバー側で発行) |
| 後片付け | 定期的な初期化の仕組みが必要 | 期限切れゲストを削除するだけ |
| 実装量 | 小 | 中 |

B を採用する。A は手軽だが、公開環境では他の閲覧者の操作で見た目が崩れる。

### 5-2. 仕様

- **API**: `POST /api/v1/guest_login`
  - ゲストユーザーを新規作成し、通常ログインと同じ HttpOnly Cookie を発行して `201` を返す。
  - メールアドレスは `guest-<ランダム値>@example.invalid` (`.invalid` は実在しないことが保証されたドメイン)。パスワードはランダム値で、利用者には返さない。
  - 表示名は `ゲスト-<4 桁>`。
- **DB**: `users.guest` (boolean, 既定 false, index あり) を追加する。
- **有効期限**: 作成から 24 時間 (Cookie の有効期限と同じ)。
- **後片付け**: ゲストログインのたびに、作成から 24 時間を過ぎたゲストを一定件数ずつ削除する。削除は ActiveRecord の `destroy` 経由とし、関連データ (投稿・コメント・画像) も一緒に消す。手動用に `bin/rails runner` 経由のスクリプトも用意する。定期実行の仕組みを持たない無料構成でも片付けが進む。
- **ゲストの制限**
  - ゲストが作る旅行記録の公開範囲は **自分のみ** に固定する (他の閲覧者に内容が見えない)。
  - 画像アップロードは 1 ゲストあたり合計 5 枚まで (保存容量の無料枠を守る)。
  - プロフィールのメールアドレス変更・パスワード変更は対象外 (現状そもそも API がない)。
  - コメント・いいね・フォローは通常どおり可能。24 時間で消える。
- **濫用対策**
  - IP 単位の回数制限: 10 分に 5 回まで (P1-3 と合わせて公開先で有効になることを確認する)。
  - 有効なゲストが一定数 (初期値 200) を超えたら新規発行を止め、「現在混み合っています」と返す。
- **画面**
  - ログイン画面とトップの未ログイン時ヘッダーに「ゲストとして試す (登録不要)」ボタンを置く。
  - ゲスト中はヘッダーに「ゲストモード: 24 時間後にデータは削除されます」と表示する。
  - ボタンは `type="button"` とし、非同期処理はハンドラ関数の中で例外を処理する (CLAUDE.md §12-3 / §12-7)。

### 5-3. 受け入れ条件

- Given 未ログイン / When `POST /api/v1/guest_login` / Then `201`・Cookie 発行・`guest: true` のユーザーが 1 件増える
- Given ゲストでログイン中 / When 公開範囲 `public` で旅行記録を作る / Then 公開範囲は自分のみで保存される
- Given ゲストが 5 枚アップロード済み / When 6 枚目を送る / Then `422` と上限のメッセージ
- Given 作成から 24 時間を過ぎたゲスト / When 別の訪問者がゲストログイン / Then 期限切れゲストと関連データが削除される (孤立レコード 0 件)
- Given 有効なゲストが上限数に達している / When ゲストログイン / Then `503` と混雑メッセージ
- Given ゲストでログイン中 / When 他人の旅行記録の本人専用セクション (予算・メモ等) を取得 / Then 通常ユーザーと同じく見えない (件数などの派生値も含む。§12-5)
- Given ログイン画面 / When 「ゲストとして試す」を押す / Then トップへ遷移し、ヘッダーにゲスト表示が出る

### 5-4. セキュリティ確認

- 既存の対策 (E-H1 汎用エラー / E-H2 応答時間の平準化 / E-M2 ログアウト時のトークン無効化) を壊さないこと。
- ゲストの権限は通常ユーザー以下であること。管理系の操作は存在しないが、今後追加する場合はゲストを除外する。
- `docs/セキュリティ自己監査.md` にゲスト関連の確認項目を追記する。

## 6. デモデータ設計 (F-DEMO-01)

- **投入方法**: `bin/rails demo:seed` (rake タスク) を追加する。何度実行しても重複しない (冪等)。
- **公開環境での実行**: 環境変数 `DEMO_SEED_CONFIRM=1` が無いと production では動かない。
- **デモユーザー**: 4〜5 名。パスワードはランダム値で、誰もログインできない (閲覧専用の登場人物)。
- **内容**
  - 旅行記録 20 件前後。カテゴリ 9 種をすべて使い、日ごとの記録・タグ・公開範囲をばらす。
  - コメント・いいね・フォロー・お気に入り・通知を相互に散らし、ゲストが入った瞬間に「人が使っている」画面にする。
  - 画像は現行どおり未設定時の代替画像を使う (保存容量を使わない)。
- **既存 seed との関係**: `db/seeds.rb` (開発用の 3 アカウント) はそのまま残す。

## 8. 公開環境の無料構成案 (P1-1)

| 役割 | 候補 | 無料枠の要点 | 確認方法 |
|---|---|---|---|
| アプリ (Rails + ビルド済み Nuxt) | Render Free | 0.1 CPU / 512 MB。月 750 時間。15 分アクセスが無いと停止し、復帰に約 1 分 | 公式ドキュメント |
| DB | TiDB Cloud Starter | MySQL 互換。1 インスタンスあたり月 5 GiB・5,000 万 RU。同時接続 400。東京リージョンあり | 公式ドキュメント |
| 画像 | Cloudflare R2 | 保存 10 GB/月。外部への転送は無料。S3 互換 | 公式ドキュメント |

- **同一オリジン配信**: Cookie が `SameSite=Lax` のため、Nuxt のビルド結果を Rails から配信し、画面と API を同じオリジンにする。
- **メモリ実測**: 本番用イメージを 512 MB / 0.1 CPU に制限して起動した結果、アイドル 113 MiB・30 リクエスト後 129 MiB・メモリ不足による停止なし・全件 `200` (平均 0.58 秒)。起動は 89 秒 (うち約 15 秒は S3 認証情報の探索待ちで、R2 のキーを設定すれば消える)。
- **本番用 DB の整理**: 本番設定にあるキャッシュ・ジョブ・WebSocket 用の DB 3 つは現状使っていないため、1 つにまとめる。
- **未確認事項**: TiDB 上でマイグレーションと全テストが通るか / 0.1 CPU での画像リサイズ速度。移行作業の最初に確認する。
- **採用しなかった候補**
  - AWS の継続: ロードバランサー・コンテナ・DB で月数十ドル。RDS の MySQL 8.0 は 2026-08-01 から延長サポート料金の対象。
  - Oracle Always Free: 7 日間 CPU・ネットワーク・メモリの使用率がすべて 20% 未満だと回収される。アクセスの少ない公開デモとは相性が悪い。
  - 静的配信のみ: 表示は速いが、マルチユーザー機能を見せられない。
